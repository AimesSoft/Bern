# Bern Web design guidelines

- Version: v0.6
- Bern interface notes updated: 2026-10-17 (explicitly prominent controls and shared capsules).
- Official sources checked on: 2026-10-10, Asia/Shanghai
- Phase: visual and interaction guidelines for the Web backend ("Web app and WebUI" in the [architecture design](../Design.md) requires them to be written up separately first)
- Related: [Bern architecture design](../Design.md), [adaptation guidelines](README.md)

The Web has no unified platform style guide. This document is the visual language Bern defines for the Web target: **Bern's own neutral web style**. It distills the practices shared by web design systems and mature web apps, with a style close to web apps such as Linear, Vercel and GitHub; as a whole it does not copy Material, Fluent or any one company's visual language, and it does not imitate desktop operating system windows. Individual controls borrow mature forms by project decision: the switch takes a form similar to Fluent 2, and the slider thumb is a disc in the page background color with a 2 px accent-color ring; neutral colors take a cool gray scale (zinc: dark page #09090B, fills #18181B and #27272A); only shape and size are borrowed, and all colors come from Bern's theme core (`bern-theme`). Except for the W3C specifications cited in the "Official basis" section, the rules in this document are Bern's design decisions.

## 1. Principles

- **The page is the app.** The main window draws no window chrome, title bar or window buttons; the web has no concept of a "window", and secondary interfaces are presented as dialogs or side panels. Draggable floating windows appear only when the app explicitly declares `presentation: floating`.
- **Quiet surfaces, clear hierarchy.** The page is a solid-color canvas, and content groups use thin-bordered cards; color is used only for primary actions, selection, focus and status, not for large areas of brand color or decorative gradients.
- **Interaction feedback uses a highly saturated accent color.** Selected items in the sidebar and in vertical navigation are filled with the accent color, and the selected tab, a switch's on state and a slider's selected range all use the accent color; navigation items have no vertical bar on the left. Icon buttons are the exception: they are Ghost buttons with no plate, and hover and press lay down a light neutral background.
- **Web density and scale.** Body text is 14 px; buttons, input fields, dropdown menus and icon buttons are 36 px tall; under a coarse pointer, controls and tap areas are enlarged across the board. The web has no capsule-shaped buttons: buttons, split buttons, menus and pickers that declare `shape: capsule` are just standard controls with the standard height and corner radius; only button-style toggles are capsule-shaped chips.
- **One color algorithm.** The generated CSS references only `--bern-*` variables, and component styles contain no literal colors; light, dark and increased contrast are generated by the same algorithm, and apps write no light or dark branches at all.
- **Browser-hosted parts are not disguised.** Scrollbars and text selection are drawn by the browser, and Bern uses `color-scheme` to make them match the current mode. Dropdown menus are drawn by Bern, so that they match the page's style and light or dark mode and behave the same in every browser.
- **Semantics do not rely on color alone.** Selection, errors and disabled states also keep text, icons, shape or accessible state.

## 3. Metrics

### 3.1 Grid and corner radius

- Spacing uses a 4 px unit: 8–12 inside controls, 16 within a row, 24 between cards, 24 page margin (16 on narrow screens), 32 between sections.
- Corner radius: controls and icon buttons 8 px; cards, menus and dropdowns 8 px; dialogs and floating windows 12 px; switches, chips and capsule-shaped markers fully rounded.
- 1 px borders: cards and separator lines use `separator`; controls that are identified by their boundary (input fields, checkboxes) use `control.border`.

### 3.2 Fonts and font sizes

Font stack: `Inter, system-ui, -apple-system, "Segoe UI", "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", "Noto Sans", "Noto Sans CJK SC", sans-serif`; Chinese pages (`<html lang>` is `zh-*`) switch to `Inter, "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei UI", "Microsoft YaHei", "Noto Sans CJK SC", system-ui, sans-serif`, so that Latin letters and Chinese characters use the same font and lines of mixed text are not made taller by the metrics of two fonts. Inter is used only if it is installed on the system; Bern does not download fonts with the page. Times and counts use `tabular-nums`.

## 4. Color

### 4.1 Theme snapshots to CSS

- At build time, `bern-theme` generates four snapshots, standard contrast and increased contrast for each of `light` and `dark`, written as `--bern-<role>` variables on `:root` and selected by `prefers-color-scheme` and `prefers-contrast: more`. The first frame is already in the correct mode.
- With `[theme] mode = "light"` or `"dark"`, only the corresponding mode is output; `system` follows the browser preference, and when the preference changes, everything switches in the same style recalculation, without rebuilding the DOM and without losing focus, IME composition or edited content.
- `:root` declares `color-scheme`, so that browser-hosted parts switch between light and dark in step.
- With `forced-colors: active`, system color keywords (`Canvas`, `CanvasText`, `ButtonFace`, `ButtonText`, `Highlight`, `HighlightText`, `GrayText`) are used instead, and selection and focus switch to outlines.

### 4.2 Roles

Each role declares its pairings, and solving guarantees only the declared pairings.

| Role | Use | Declared pairings |
| --- | --- | --- |
| `surface.canvas` | Page background, cards | — |
| `surface.panel` | Sidebar, table headers, secondary areas | — |
| `surface.raised` | Dialogs, menus, dropdowns, floating windows, input field background | — |
| `surface.host` | Page background under the dialog scrim and between floating windows | — |
| `text.primary`, `text.secondary`, `text.placeholder` | Body text, secondary descriptions, input hints | ≥ 4.5:1 against each surface and against the hover and pressed backgrounds |
| `icon.primary`, `icon.secondary` | Action icons, auxiliary icons | Same as above, ≥ 3:1 |
| `accent`, `on_accent` | Primary buttons, selected items in the sidebar and vertical navigation, switch on, slider selected range, icon button hover; text and icons on top of them | `on_accent`/`accent` ≥ 4.5:1; `accent` against the canvas, panel and raised layers ≥ 3:1 |
| `accent.text` | Links, plain buttons, text of the selected tab, icon button pressed and selected; starts from the lightness of `accent` and moves only as far as readability requires, staying as vivid as the accent color | ≥ 4.5:1 against each surface |
| `status.success`, `status.warning`, `status.error` and `on_*` | Status foregrounds, and foregrounds on status backgrounds | Foregrounds ≥ 4.5:1 against each surface; `on_error`/`status.error.surface` ≥ 4.5:1 |
| `control.border` | Controls identified by their boundary, such as input fields and checkboxes | ≥ 3:1 against the surface they are on |
| `separator` | Card borders, separator lines, outlines of buttons with text (decorative) | Contrast not checked, classified as decorative |
| `control.track`, `control.thumb` | The slider's unselected track; the thumb and the thumb's outer ring | track ≥ 3:1 against the surface; thumb ≥ 3:1 against track and accent |
| `media.played`, `media.track` | The played part and the unplayed track of the video progress bar | played ≥ 3:1 against track and panel; track is decorative |
| `focus.indicator` | Focus ring | ≥ 3:1 against each surface |
| `hover.overlay`, `pressed.overlay` | Hover and pressed backgrounds of rows, navigation items and plain controls (opaque) | Text on them still meets its own pairing |
| `disabled.foreground`, `disabled.surface` | Disabled text and disabled background | Unavailable controls are classified separately: foreground/surface ≥ 3:1 |
| `scrim` | Dialog scrim | The dialog on the scrim is an opaque raised surface |

## 5. Components

Component semantics follow the [`bern-ir` component specification](../../crates/bern-ir/src/spec.rs); the sections below specify the Web presentation, roles and keyboard behavior.

### 5.1 Windows: WindowSet and Window

- **App bar.** At the top of the page is a 48 px app bar (`surface.canvas`, bottom border `separator`): at the leading end is the app name (`headline`); at the trailing end is the settings button (a `gearshape` icon button), which appears when the app declares a window with `role: settings`, and Ctrl / Cmd + , has the same effect. Only when there is a `presentation: floating` window does a window switcher bar appear in the middle of the app bar, with the current window's item filled with the accent color.
- **The main window is the page.** The main window's content fills the area below the app bar directly, with no title bar, window buttons or shadow. After the main window is closed by a command, that area shows the app name and an "Open {window title}" button, centered; the page itself does not close.
- **Dialogs (the default presentation of secondary windows).** The settings window and other secondary windows are presented as centered dialogs:
  - The width is the window's declared width (560 px when not declared), at most the viewport minus 32 px; the height fits the content, at most 85% of the viewport, and the content area scrolls.
  - 56 px header: the title (`title3`) at the leading end and the close button (an `xmark` icon button) at the trailing end; there is no minimize or maximize. A dialog whose content has a sidebar (`SplitView`) has no such row: the sidebar runs up to the top, the detail column's page header shows the title of the selected page (28 px from the left), and the close button is at its trailing end (14 px from the right).
  - When it is opened with a pointer, focus goes to the dialog itself; when it is opened with the keyboard, to the first control; an open dialog never leaves an input field sitting in focus.
  - The scrim is `scrim`. Tapping the scrim, pressing Esc or clicking the close button all request close and go through the close protocol (when there is unsaved content, a confirmation is shown first). When the dialog opens, focus enters it; after it closes, focus returns to the element that opened it.
  - A root `Tabs` inside a dialog is presented as vertical navigation on the left (180 px wide) when the width is ≥ 640 px, and otherwise as top underlined tabs.
- **Floating windows (`presentation: floating`).** They appear only when the app explicitly declares them: a draggable, resizable panel (`surface.raised`, 12 px corner radius, shadow) with a 40 px title bar and minimize, maximize / restore and close at the trailing end; a minimized window is restored from the app bar's switcher bar; releasing after a drag or resize commits one `window.move` or `window.resize`; keyboard: with the title bar focused, arrow keys move the window and Shift + arrow keys resize it.
- **Narrow screens (viewport width < 768 px).** Dialogs and floating windows fill the area below the app bar, and the header keeps the title and the close button.
- **Window actions.** Pages and dialogs only have activate and close; minimize, maximize, move and resize are unavailable, `window.list` lists them truthfully, and running them returns `target_unavailable`. The presentation is reported as `Virtual`.
- **Close confirmation.** Presented as a modal confirmation dialog inside the owning window (the Dialog (Modal) pattern), with focus confined to the confirmation dialog; Esc is equivalent to "Cancel".

### 5.2 SplitView, Sidebar, Detail

- The sidebar is 232 px wide (draggable within 200–320 px, Window Splitter pattern), `surface.panel`, with a 1 px `separator` on its right edge (not taking up content width); 10 px is left on all sides, with an extra 40 px title bar row at the top (absent inside dialogs); the detail column is `surface.canvas`. When the app declares a width, the width is fixed and cannot be dragged.
- On wide screens, the very first item at the leading end of the detail page header is the sidebar button (a `sidebar.left` icon button, named "Hide Sidebar / Show Sidebar"): the sidebar, together with its search, header and footer, slides out toward the leading edge as a whole and hides, and pressing again slides it back; the button stays where it is. It is not shown on narrow screens.
- The sidebar header (`SidebarHeader`) has padding of 6 top, 8 left and right, 14 bottom, at weight 600; Search is 36 px tall; Section titles are `caption2`, `text.secondary`, with 16 px above them; the footer (`SidebarFooter`) has padding of 10 top, 6 left and right, with no separator line.
- SidebarItem uses the `nav_item` recipe: 34 px tall, 10 px left and right padding, 8 px corner radius, an 18 px icon 12 px from the title, 13.5 px at weight 500, 2 px between items; the selected item is filled with the accent color, its text and icon are `on_accent`, and there is no vertical bar on the left. Listbox pattern: Up and Down arrow keys move and select, Home / End go to the first and last item.
- At the top of the detail column is the page header: 56 px tall, no bottom border, 24 / 16 px left and right padding, the title is the text of the selected item (17 px at weight 600), and toolbar items are at the trailing end.
- When the viewport width is < 768 px, the sidebar becomes the first page; selecting an item shows the detail, and a back button appears at the leading end of the page header.

### 5.3 Form and Section

- Form content has a maximum width of 720 px, is centered horizontally and has a 24 px page margin; inside a dialog the width is not limited, with padding of 22 top, 28 left and right, 32 bottom. When there is a `title`, it serves as the page title.
- Section: the title is above the card (13 px at weight 600, inset 2 px, 10 px from the card); the content is in a card (`surface.canvas`, 1 px `separator` border, 12 px corner radius); rows are separated by `separator`; the footnote is below the card (`footnote`, `text.secondary`). 32 px between cards, 22 px inside dialogs.
- Rows in a card: switches, checkboxes, pickers and buttons are horizontal rows with "label first, control at the trailing end", with 16 px row padding; text inputs, multiline inputs and sliders are vertical with "label above, control spanning the full width".

### 5.4 Navigation, Destination, NavLink

- Navigation is a push stack; a pushed page replaces the content area, a back button (`chevron.left`) appears at the leading end of the page header, and Esc or Alt + ← goes back; the root page stays mounted.
- NavLink is a link row that is clickable across the whole row: content first, `chevron.right` at the trailing end; hover `hover.overlay`; Enter / Space pushes.

### 5.5 Tabs and Tab

- By default, top underlined tabs (Tabs pattern, `role="tablist"`): 14 px labels, and with an icon, a 16 px icon before the label; the selected item's text and icon are `accent.text` with a 2 px `accent` underline, the others are `text.secondary`; the tab bar has a `separator` bottom border. Left and Right arrow keys switch and activate.
- Tabs at the root of a dialog are vertical navigation on the left on wide screens, with the same shape and selected style as `nav_item` (the selected item filled with the accent color, no vertical bar); Up and Down arrow keys switch.

### 5.6 Toolbar

- Located at the trailing end of the page header or dialog header, 8 px between items, 36 px tall. Button uses the standard appearance (`prominence: prominent` keeps the primary button), Picker uses the segmented appearance, and IconButton has no container. Toolbar pattern: arrow keys move focus between items.
- `ControlGroup` has no shared plate on the web: the icon buttons in the group are laid out one after another, 6 px apart; the group is also only 6 px from neighboring things in the same row (another group, a title, a spacer), whatever spacing the row declares, so it reads as one continuous row of Ghost icon buttons.

### 5.7 List and ForEach

- Inside a Section, a List is rows in the card; used on its own, it is a bordered card. Row identity is kept by `key`; insertion, deletion and reordering do not rebuild unchanged rows.

### 5.8 Text, Label, Divider, Spacer, ScrollView, Column, Row

- Text and Label use the font sizes in 3.2; Label's icon is 16 px, with 8 px between icon and text, and the icon uses `icon.secondary`.
- Divider: 1 px `separator`. ScrollView: native scrolling, `overscroll-behavior: contain`. Column and Row are flex layouts, with `gap` and `padding` in px.

### 5.9 Button and IconButton

- Button: `<button>`, 36 px tall, 14 px left and right padding, no minimum width, 8 px corner radius, 13.5 px at weight 500; with an icon, the icon is before the text, 6 px apart. The appearance selects a recipe from 4.3 by `prominence` and `role`; the `cancel` role uses standard. `shape: capsule` does not change its shape or height (the web has no capsule-shaped buttons), and the same goes for the trigger buttons of menus and pickers, which have a 14 px trailing arrow and padding of 12 left and 10 right.
- IconButton: `<button aria-label>`, default hit area 36 × 36 px, 8 px corner radius, a Ghost button: at rest only the icon (`icon.primary`), hover and press lay down a light neutral background, and the focus ring is kept. Explicit prominent provides an accent container (44 × 44, corner radius 12); ControlGroup adds no plate (see 5.6). `font_size` adjusts the icon size; for the full sizes and grouping usage see the [current component reference](../Reference/UI.md).
- Disabled: the `disabled` attribute and the recipe's disabled colors; lowering the overall opacity is not used to indicate a disabled state.

### 5.10 TextInput and Search

- TextInput: `<input>` (`secure` is `type="password"`, `multiline` is a `<textarea>` of at least 3 rows), `field` recipe, 32 px tall, label above (14 px at weight 500, 6 px from the input field); placeholder text uses `text.placeholder`.
- During IME composition, only the local display is updated; after composition ends, the text is written to the session in one go.
- Search: a leading `magnifyingglass` icon and a trailing clear button (which appears when there is content); Enter runs the declared submit action, Esc clears.
- The entry of `Search(style: palette)` is a 36 px tall outlined box with an 8 px corner radius (`separator`, page background color) and a 13.5 px placeholder; when `shortcut` is declared, the key is shown at the trailing end (on Apple systems as e.g. `⌘K`, on other systems as e.g. `Ctrl K`, 11 px at weight 500).

### 5.11 Switch

- `style: switch`: `<button role="switch" aria-checked>`, `switch` recipe. The form is similar to Fluent 2: when off, a hollow bordered track with a thumb of the same color; when on, the track is filled with the accent color and the thumb becomes `on_accent`; the thumb moves in 150 ms. Space / Enter toggles.
- `style: checkbox`: a 16 px box with a 4 px corner radius; when checked, an `accent` background with an `on_accent` checkmark.

### 5.12 Slider

- `<input type="range">`, with the track and thumb drawn by Bern using the `slider` recipe: a 6 px track with the selected range in the accent color; a 16 px thumb, a disc in the page background color with a 2 px accent-color ring, enlarged to 1.15× on hover and while dragging. `min_icon` / `max_icon` are at the two ends (16 px, `icon.secondary`).
- While dragging, only the session preview is updated; the declared submit action runs on release or when a keyboard adjustment ends.

### 5.13 Picker

- `automatic`, `menu`: a dropdown menu drawn by Bern, following the WAI-ARIA APG "Select-Only Combobox" pattern.
  - Trigger: `<button role="combobox" aria-haspopup="listbox" aria-expanded>`, with the same appearance as a standard button: 36 px tall, width following the current option, padding of 12 left and 10 right, a 1 px `separator` outline, a transparent background, 13.5 px at weight 500, a 12 px trailing `chevron.down` (`icon.secondary`), hover `hover.overlay`.
  - Popup: `role="listbox"`, placed in the browser's top layer (Popover API), not clipped by cards, dialogs or scroll containers; at least as wide as the trigger, and it opens upward when there is not enough space below; `menu` recipe, 8 px corner radius, 4 px padding.
  - Options: `role="option"`, 32 px tall, 8 px left and right padding, 6 px corner radius; the selected item has a trailing checkmark and `aria-selected="true"`.
  - Keyboard: Enter, Space, ↓ and Alt + ↓ open it and put the active item on the current option; ↑ ↓ move the active item, Home / End go to the first and last, typing characters jumps to the option that starts with them; Enter or Space selects and closes; Esc closes without changing the value; Tab selects the active item, then closes and moves focus away. Tapping outside the popup closes it.
  - Selection goes only through the same selection closure as touch and external entry points; opening and closing the popup are not written to the session.
- `segmented`: a segmented control in the Radio Group pattern, `segmented` recipe, with a subtle shadow on the selected segment.
- `chips`: a row of pill buttons in the Radio Group pattern (30 px tall, 12 px left and right, 13 px at weight 500), `chip` recipe, wrapping within the group with 8 px spacing. When it is placed directly inside a `Flow` and is `label_hidden`, the group container is `display: contents`, and every chip is a child of the Flow.
- `radio`, `inline`: a vertical single-choice list, each item with a 16 px circular indicator.

### 5.14 Video

- A `<video>` element, with `object-fit` determined by `fit`; the picture keeps its original colors. **The browser's native `controls` are turned off**, and Bern's standard control bar is used, placed on an opaque bar below the picture (44 px tall, `surface.panel`) rather than over the moving picture.
- Control bar: play / pause, current time / duration (`tabular-nums`), progress bar, mute, volume. An unknown duration shows `--:--`; a live stream shows "Live" and the progress bar is disabled.
- Progress and volume use a dedicated **media scrubber** (`media_scrubber` recipe) rather than reusing Slider: the played part is the neutral `media.played`, not the accent color; the thumb is a white rounded capsule similar to macOS 26 (20 × 16 px, corner radius 7, soft shadow), with a 6 px track. It is still `role="slider"` (`aria-valuetext` is the time text); arrow keys move 5 seconds at a time (volume 5% at a time), PageUp / PageDown 10% at a time, Home / End go to the start and end; dragging only updates the preview, and one seek is committed on release or when a keyboard adjustment ends.
- The loading and failed states show a progress indicator, or an error icon and text, centered in the picture area.

### 5.15 Query

- First load: a centered progress indicator and the `loading` text; refresh: the data is kept, with a row of progress and text shown above it; failure: with no data, a centered error icon, text and "Retry", and with data, a row with the error and "Retry" above the data; empty result: a centered 32 px icon (`tray` by default) and the `empty` text.

### 5.16 Adaptive and Layout

- `Adaptive` is a block container that fills the available width and measures its own width with `ResizeObserver`: below `[layouts].compact_below` it mounts the `compact` layout, otherwise the `expanded` layout. When the container is not rendered (its width cannot be known), it keeps the previous size.
- Switching rebuilds only the layout's content; session drafts and engine state are not in the view tree and are not affected. If the new layout has a control with the same `data-bern-target` as the control that had focus before the switch, focus moves to it; when the control with that name is inside a menu that is not open, focus moves to that menu's button.
- Inside a card (Section), each child of the layout takes its own row, with separator lines like the card's other rows.
- With an `id`, it is registered with the `adaptive` role, and its value is the current size.

### 5.17 Menu and MenuItem

- Follows the WAI-ARIA APG Menu Button pattern: the trigger is a standard button (icon, label, trailing `chevron.down`) with `aria-haspopup="menu"`; the menu is a popup in the browser's top layer (Popover API, `role="menu"`) that looks the same as the dropdown menu (`menu` recipe) and is not clipped by cards, dialogs or scroll containers.
- Menus and popover panels open from the trigger button: with the button's side as the origin, they scale from 0.9 to 1 along a bouncy spring (period 0.5 s, damping 0.62) while fading in within 120 ms; when the trigger button is in the right half of the page, the popup's trailing end aligns with the button's trailing end and it expands to the left. With Reduce Motion, there is only a 150 ms fade-in.
- Menu items are buttons with `role="menuitem"`, 32 px tall, with a 16 px icon in front; `role: destructive` uses `status.error` text; `Divider` is a 1 px `separator`. Hover and keyboard focus have a `hover.overlay` background.
- Keyboard: ↓, Enter and Space open the menu and focus the first item, ↑ opens it and focuses the last item; inside the menu, ↑ ↓ move cyclically, Home / End go to the first and last, typing a letter jumps to the item that starts with it; Enter / Space run the item and close the menu, and focus returns to the button; Esc closes the menu (without closing an outer dialog) and returns to the button; Tab closes it.
- Each menu item is registered as a button control by its own `id`, and `ui.activate` from an external entry point goes through the same command closure even when the menu is not open.

### 5.18 LanguagePicker

- Looks and behaves the same as the dropdown menu (5.13); the options are the supported languages, each shown by its name in that language (`Intl.DisplayNames`, e.g. "简体中文", "English").
- After a selection, the localized text of the whole page switches in the same update, and `<html lang>` and the page title change with it; windows, dialogs, drafts, navigation and focus are kept.

## 6. States and focus

- **Focus ring.** Only on `:focus-visible`: a 2 px `focus.indicator` outline, offset outward by 2 px, with the corner radius following the control; for controls inside cards, the focus ring is inset to avoid being clipped. The focused element is scrolled into view and is not covered by the app bar or the page header.
- **Hover.** Applied only under `(hover: hover)`.
- **Pressed.** `:active` applies the recipe's pressed state.
- **Combined states.** Selected and hovered keeps the selected color; with an error and focus, the boundary keeps the error color and the focus ring shows as usual; disabled blocks interaction but keeps the selected and error semantics.

## 7. Motion

- Color, background and border changes take 150 ms `ease-out`; a dialog opens with a 180 ms opacity change and a 0.98→1 scale, and the scrim fades in; menus and popover panels pop out from the trigger button (see 5.17); push navigation has no movement animation.
- With `prefers-reduced-motion: reduce`, only opacity changes of no more than 150 ms are kept.

## 8. Icons

- The Bern icon set uses SF Symbols naming. The Web backend draws icons with [Lucide](https://lucide.dev) (`lucide-static` v1.54.0): each name maps to one Lucide icon, and the mapping table is in `bern-backend-web`; the Lucide SVGs in use are stored unchanged in the repository, and nothing is fetched from the network at build time.
- The appearance is Lucide's design guidelines: a 24 × 24 canvas, a 2 px centered stroke, round caps and round joins, with the color `currentColor`, following the recipe of the control the icon is in.
- Filled names (ending in `.fill`): Lucide officially provides no filled versions, so Bern adds a fill to the outline version and keeps the 2 px stroke, so that the filled and outline versions have the same contour. Each filled name states its fill method in the mapping table:
  - **Full fill**: icons that have only closed shapes, such as `play.fill` and `pause.fill`.
  - **Partial fill**: only the specified shapes are filled and the rest stays as lines, e.g. `speaker.wave.3.fill` fills only the speaker, and the sound waves stay lines.
  - **Cutout**: the outer shape is filled, then the inner lines are cut out of it, e.g. `xmark.circle.fill` is an X cut out of a solid circle.
- When an app uses a name that is not in the mapping table, the build fails and points to that declaration. Color images and brand graphics are content and do not take part in theme coloring.
- License: Lucide is under the ISC license, and its icons derived from Feather are under the MIT license; both require the copyright and license notices to be kept with copies. The generated page directory contains `THIRD_PARTY_NOTICES.txt` with the full text of both licenses; the icons with added fills are modified versions based on Lucide and are not published as official Lucide icons.

## 9. Accessibility and localization

- The root element's `lang` is the resolved language.
- Role mapping: Menu → `button` (`aria-haspopup="menu"`) + `menu` / `menuitem`; LanguagePicker → `combobox` + `listbox`; Button → `button`; IconButton → `button` + `aria-label`; Switch → `switch` / `checkbox`; Slider → native range; media scrubber → `slider`; Picker automatic / menu → `combobox` + `listbox` / `option`; Picker segmented / radio / chips → `radiogroup` + `radio`; Tabs → `tablist` / `tab` / `tabpanel`; Sidebar → `listbox` / `option` (`aria-selected`); NavLink → `link`; dialog → `dialog` (`aria-modal`, `aria-labelledby`); floating window → `dialog` (non-modal); close confirmation → `alertdialog`; Query progress and error rows → `status` / `alert`.
- Control identity is written to `data-bern-target`, matching the target ID of `ui.inspect`.

## 10. Bern acceptance
